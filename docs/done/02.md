# Job 2: classifier and stores (2026-10-22/23)

Branch `job/2-classifier-stores`. Decisions 28 to 39 are in

## What was built

- **One classifier, server-side.**
  - `public.classify_item(household, name)` checks three things in order:
    1. The household's learned corrections.
    2. A German seed dictionary of 1070 terms.
    3. The fallback, "Sonstiges".
  - The items insert trigger calls it, so the app uses it. `add_items` calls
    it, so MCP and Siri use it too.
  - `public.item_key` normalizes names. It lowercases, folds umlauts and
    accents (`ä` and `ae` both become `a`), turns `ß` into `ss`, drops
    quantities and units, and strips one plural ending per word.
  - Matching uses dictionary phrases, then the whole name. Then a frozen
    marker: "TK", Tiefkühl-, tiefgekühlt or gefroren means Tiefkühl. Then
    compound suffixes (Vollmilch → milch), then prefixes.
  - Migration `supabase/migrations/20261022233800_classifier_stores.sql`.
- **Dictionary as data.** `supabase/classifier/dictionary.tsv` is the
  reviewable source. `generate.ts` turns it into the migration
  `20261022233900_classifier_dictionary.sql`. A Deno test, run in CI and in
  `verify.sh`, fails if the two differ.
- **Learning in a trigger.**
  - Changing an item's category is a correction. That covers the category
    picker in the edit sheet, drag between groups, and a plain `UPDATE`
    from MCP. It is stored per item key with a count, and the latest
    correction wins.
  - Changing an item's store, or ticking it off inside a store view, teaches
    the item→store memory. A new item with no store gets the remembered one.
  - Deleting a category moves its items without teaching anything.
- **Category management.** Menu → "Kategorien verwalten".
  - Rename by tapping a category.
  - Reorder the route by drag.
  - Add a category. Duplicate names get a German message.
  - Delete a category; its items move to a category you pick, by default
    Sonstiges, which cannot be deleted.
  - RPCs: `create_category`, `reorder_categories`, `delete_category`.
- **Stores.**
  - dm, Lidl and Edeka start with researched walking orders, with sources
    in `docs/STORE_LAYOUTS.md`.
  - dm hides fresh, chilled, meat and frozen. Untagged items in hidden
    categories sit behind a footer button that shows them.
  - The store picker sits under the add field: "Alle", dm, Lidl, Edeka. The
    add field still has focus on open.
  - "Reihenfolge bearbeiten" opens the store's order: drag to reorder, and a
    switch per category for "gibt es hier" (`set_store_layout`).
  - An item typed in a store view is tagged to that store.
  - The edit sheet has a "Geschäft" picker for tagging by hand.
- **`add_items(p_household, p_names, p_store)`.** This is the shared add path
  for jobs 3 and 4, posted on the board. It parses quantities like the app
  does, for example "1 Packung Eier" or "0,5 kg Hackfleisch". It classifies
  each item, applies the remembered store, and returns the existing row
  instead of a duplicate.
- **Realtime.** Categories, stores and store layouts reload live in every
  member's app. Reloads after a reorder's many row events are coalesced.
- **Accessibility fixes found by e2e.**
  - Group headings were merged into the first item's button.
  - Drag-handle labels renamed their rows.
  - Stores came back in reverse, because postgrest-dart's `order()`
    defaults to descending.

## Review 0 fixes

- Fixed the frozen classification. "TK-Spinat", "TK Spinat",
  "Tiefkühlspinat", "tiefgekühlte Erbsen" and "gefrorene Himbeeren" now go
  to Tiefkühl. A whole-name term still wins, so Tiefkühlbeutel stays
  Haushalt.

  `s` inside compounds, which broke "Dosenmais". Added Zewa, Persil, Pril,
  Nivea and Maggi. Pet food stays in Haushalt (DECISIONS 29).
- Rebased on main (1b). The migrations are re-timestamped after
  `20261022190526` and 03's `20261022205008`.
- Explained the grey Edeka chip in the dm screenshot. It was the pointer's
  hover, not focus or selection: an experiment showed it clears when the
  mouse moves away. The store screenshots are now taken with the pointer off
  the chips.
- DECISIONS 36 now says that a tick in a store view makes the item that
  store's from then on.
