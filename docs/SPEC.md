## Requirements
1. Fast capture: opening the app focuses the add-item text field immediately (keyboard up on mobile, cursor in field on web), with the shopping list visible on the same screen, no separate tab or screen for adding. Enter adds the item and keeps focus for the next one. Ticking an item off removes it from the active list (with a short undo snackbar; ticked items go to a "recently bought" history usable for quick re-add).
2. Classifier: every new item is sorted into a category automatically and learns from corrections (e.g. when an item is moved to another category, via drag or a category picker). Seed categories, in this default store-route order:
   Obst & Gemüse, Brot & Backwaren, Kühlregal, Fleisch/Wurst/Fisch, Vorrat & Konserven, Süßes & Snacks, Getränke, Tiefkühl, Haushalt, 👶 Drogerie.
   Pipeline (all free, deterministic, runs server-side in Postgres or an Edge Function so the app, MCP and Siri share it):
   a. learned per-household item→category memory (normalized item name: lowercase, trimmed, umlaut/ß-normalized, quantities and units stripped, simple German plural/singular stemming), updated on every correction (latest correction wins; keep counts);
   b. German keyword/seed dictionary (ship a good one: several hundred common German grocery and drugstore terms incl. compounds, e.g. "Vollmilch"→Kühlregal via suffix/compound matching, "Klopapier"/"Toilettenpapier"→Haushalt or Drogerie (decide and document), "Windeln"→👶 Drogerie);
   c. fallback category (e.g. "Sonstiges" shown last, or the most plausible default; document).
   Categories are editable per household (rename, reorder, add).
3. Stores: dm, Lidl, Edeka seeded, each with its own category order matching the store layout (editable by drag). Item→store memory: remember which store an item is usually bought at (learned from where it gets ticked off in a store view, plus manual tagging). Untagged items can be bought at any supermarket. A store picker switches the view: "Alle" (default route order) or a store, which shows that store's tagged items plus untagged items, grouped and ordered by that store's category order (dm shows its relevant categories; decide how non-drugstore untagged items appear in dm view and document).
4. Shared household: Peter and Lea share one household (invite by code or link in-app; do NOT send any invite). Supabase Auth (email+password and magic link; Sign in with Apple can be prepared but needs Peter's config). Supabase Realtime: an item ticked off on one phone disappears on the other immediately; adds, moves and edits sync live too. Handle offline/reconnect sanely (optimistic UI, resync on reconnect).
5. MCP server: a Supabase Edge Function speaking MCP over streamable HTTP (current MCP spec), with tools to list items (optionally per store), add items (one or many, auto-categorized), tick items, move items (category and/or store), and list categories/stores. Auth: OAuth 2.1 per the MCP authorization spec, with Supabase Auth as the authorization server via Supabase's OAuth 2.1 Server feature (research the CURRENT Supabase docs: docs "OAuth 2.1 Server" / "MCP authentication"; dynamic client registration if supported). The function must serve Protected Resource Metadata (RFC 9728, /.well-known/oauth-protected-resource), return 401 with the WWW-Authenticate resource_metadata header, validate access tokens (JWT via Supabase JWKS / asymmetric signing keys) and audience, and the Flutter web app must host the OAuth consent/authorization UI page that Supabase's OAuth server redirects to. Fallback: revocable personal access tokens (PATs) created and revoked in the app settings, shown once, stored only as a hash, scoped to the household, accepted by the MCP function and the Siri endpoint as Bearer tokens.
6. Voice: an HTTP endpoint (Edge Function) for a German Siri Shortcut: POST one sentence (PAT auth), e.g. "Milch, zwei Gurken und Klopapier", split it into items (commas, "und", "sowie", "noch", "auch", filler like "bitte", "wir brauchen", "schreib auf", number words "zwei"→2, units "1 kg", "eine Packung"), then categorize each through the classifier and return a short German confirmation that Siri speaks ("Hinzugefügt: Milch, 2 Gurken, Klopapier"). Ship step-by-step Shortcut setup instructions in German (docs/SIRI_SHORTCUT.md, with the exact actions: Diktieren → Inhalte von URL abrufen (POST, JSON, Authorization header) → Ergebnis sprechen). In-app speech-to-text too if free (e.g. speech_to_text package using on-device recognition, de-DE), feeding the same splitter.

- MCP OAuth flow test (discovery → dynamic client registration if supported → authorization code + PKCE through the consent page → token → MCP initialize/tools/list/tools/call) plus a PAT test (create, use, revoke → 401);
- Siri endpoint parsing test (table of German sentences → expected items/quantities/categories, plus an HTTP test with a PAT).
Plus unit/widget tests in Flutter, Deno tests for functions, and SQL/RLS tests (pgTAP; prove a user from another household can't read or write). Take screenshots for the PRs.
