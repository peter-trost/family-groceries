# Job 3b: MCP follow-ups (2026-10-23)

Branch `job/3b-mcp-followups`. It closes the four open edges that job 3's
review left (`jobs/03-mcp-oauth-tokens/review.0.md`) and re-runs the
Inspector smoke test.

## What changed

1. **verify.sh and e2e work on any port block.**
   - `scripts/lib.sh` `supabase_up` exports `MAILPIT_URL`. It fails if
     `supabase status` lacks the URL, key or Mailpit URL.
   - `e2e/stack.ts` reads each value from the environment, or else from
     `supabase status`, and throws if one is missing. There is no 543xx
     fallback any more.
   - The web server port defaults to `<API port prefix>80` (54621 → 54680)
     instead of a shared 3100. Before, a parallel job's server could be
     reused through `reuseExistingServer`.
   - `config.toml` allows loopback redirects on any port.
   - CI exports `MAILPIT_URL` too.
   - The fake OIDC provider runs on the port in the checkout's
     `config.toml` Keycloak URL (`<prefix>99`), not a shared 54399 that
     another job's run could stop midway.
   - Playwright runs one worker locally, per the box's RAM rule.
2. **MCP `add_items` goes through `public.add_items`** (`mcp/list.ts`).
   - That brings quantity parsing ("2 Gurken"), learned category and store,
     and dedupe by item key ("Gurke" = "2 Gurken").
   - An explicit `category` is applied as an update, so it is learned like
     a correction.
   - 04's branch had only switched the dedupe to `item_key` and still
     inserted directly. This branch replaces that whole function body.
3. **Tool descriptions.**
   - `add_items` and `move_item` now describe the learning that really
     happens: the household's corrections, the dictionary and the
     remembered store.
   - `tick_items` says that a repeated call changes nothing (review item 5).
4. **Disconnecting cuts access off at once.**
   - Supabase cannot revoke an issued JWT. Its discovery document has no
     revocation or introspection endpoint.
   - `revokeGrant` does delete the client's sessions. `authenticate()` now
     accepts a JWT only while its `session_id` row exists in
     `auth.sessions` for that user and OAuth client. Otherwise it answers
     `401 invalid_token`.
   - App session tokens get the same check, so signing out also ends voice
     access. `voice.spec.ts` covers this: the unexpired token of a
     signed-out session gets 401.
   - PATs were already checked on every request. The e2e test now asserts
     the first call after revoking.
5. **Inspector smoke test.** `scripts/mcp-inspector-smoke.sh` runs the
   official `@modelcontextprotocol/inspector@2.12.0` CLI against the local
   stack. It creates a throwaway user and PAT, calls every tool, revokes
   the PAT, then checks for 401. The output is in
   `docs/screenshots/03b/inspector-smoke.txt`.

Docs: `docs/MCP.md` (tools table, session check, a new section
"Disconnecting and revoking", tests), `docs/DECISIONS.md` 3b.1–3b.3, and
`docs/NEEDS_PETER.md` section 5 (check after the hosted deploy).
