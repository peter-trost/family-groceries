# Job 1b: Sign in with Google and Apple (2026-10-22)

PR: https://github.com/peter-trost/family-groceries/pull/6

## What was built

- **Sign-in screen.** It offers Google, Apple, email and password, and a
  magic link. The buttons follow Google's and Apple's guidelines and carry
  the German labels "Mit Google anmelden" and "Mit Apple anmelden". A
  provider's button shows only when the build has its public client
  configuration. The screen is a reusable `SignInPanel(returnPath: …)`
  (`app/lib/session/login_screen.dart`) for job 3's OAuth consent page.
- **Flows** (`app/lib/session/social_sign_in.dart`, `plugin_sign_in.dart`):
  - Google is native on iOS and Android, and Apple is native on iOS. Each
    goes to `signInWithIdToken` with a nonce: the provider gets the SHA-256
    hash, Supabase gets the raw value, and the nonce check stays on.
  - Apple on Android and both providers on web use the OAuth redirect (PKCE).
    Android returns through the deep link
    `com.petertrost.familygroceries://login-callback`, which now also
    carries mobile magic links.
  - Cancel and errors show in German ("Anmeldung abgebrochen", "Anmeldung
    fehlgeschlagen: …"), including errors that come back on a redirect's
    return URL.
- **Apple's name.** It is stored on the first native sign-in. Migration
  `20261022190526_provider_display_names.sql` copies provider names
  (Google's `full_name`, Apple's stored name) into `profiles.display_name`,
  but never over a name the user chose.
- **Identity linking.** Supabase's automatic linking puts the same verified
  email into one user, and so one household. This is verified locally for
  password then provider, provider then magic link, and provider then
  provider.
- **No Google script on web.** The app uses Google Sign-In's platform
  interface with only the Android and iOS implementations. The app-facing
  package loaded `accounts.google.com/gsi/client` on every web page view.
- **Config without secrets:**
  - `supabase/config.toml` has `[auth.external.google|apple]` (disabled,
    `env()` references).
  - `app/config/auth.json` holds the public client IDs for
    `--dart-define-from-file`; it is empty until Peter fills it.
  - `.env.example` lists every variable.
  - iOS has the Sign in with Apple entitlement and the reversed Google
    client ID URL scheme from `ios/Flutter/Auth.xcconfig`; a unit test
    keeps that in step with `auth.json`.
  - Android has the deep-link intent filter and no SHA keys in code.
- **Hosted config script.** `scripts/configure-social-auth.mjs` enables a
  provider through the Management API only when its credentials exist, and
  generates Apple's 6-month client secret from the `.p8` key. It ran once
  and added only the app deep link to the hosted redirect allow list. Google
  and Apple stay disabled until Peter's credentials exist.
- **Local test identity provider.** `e2e/fake-oidc.mjs` acts as a test-only
  `[auth.external.keycloak]`. GoTrue runs the same ID-token, nonce, audience
  and linking code for it as for Google and Apple, which cannot be faked
  locally because their issuers are hard-coded.
- **Docs.**
  - `docs/AUTH.md`: research with links, flows, linking rules and the note
    for job 3.
  - `docs/NEEDS_PETER.md` section 4: numbered Google Cloud, Apple Developer,
    Supabase and app steps, including SHA-1 fingerprints.
  - `docs/DECISIONS.md`: the job 1b section.

## Missing or blocked (needs Peter)

- **Provider credentials.** These need the Google Cloud OAuth clients and
  the Apple Developer Services ID and key. Every step is in
  `docs/NEEDS_PETER.md` section 4. After that, run
  `node scripts/configure-social-auth.mjs` and fill `app/config/auth.json`
  and `ios/Flutter/Auth.xcconfig`.
- **Real Google and Apple not tested.** No real Google or Apple sign-in ran
  on a device, because there are no credentials and no iPhone or Android
  device on this box. Native plugin calls are covered with mocked providers.
  The server side is covered through the fake provider. Step 18 of section 4
  is the manual check.
- **Apple client secret rotation.** It expires after 6 months; rerun the
  script before then.
- **Known limits, documented in `docs/AUTH.md`:**
  - Apple's "Hide My Email" creates a separate account, because the relay
    address never matches.
  - Signing in with a provider over an unconfirmed password sign-up removes
    that password (Supabase's pre-account-takeover protection).
